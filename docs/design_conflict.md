# 设计：冲突与时效（Conflict & Recency）

> 目标：当同一事实存在「新旧制度 / 企业制度 vs 外部法规 / 行业参考」多个值时，
> 系统必须**显式告知差异**并说明以谁为准，而不是静默选一个或拼在一起。

## 1. 要解决的问题

企业知识库里同一事实常有多个来源：

- 旧版员工手册 vs 新版员工手册（年假 5 天 vs 7 天）；
- 公司制度 vs 国家法规（公司 7 天 vs 法定 5/10 天）；
- 公司差旅标准 vs 行业参考（600 vs 550）。

检索会把它们一起召回。若不处理，模型会：

- 随机选一个值（不可解释）；
- 或把两个值都写进答案（自相矛盾）。

## 2. 设计

### 2.1 候选对筛选

两两组合证据对，用**字符 2-gram Jaccard** 过滤（阈值 0.15），只把可能相关的对送给判定器，
避免 N² 次 LLM 调用。

### 2.2 矛盾判定

LLM 判定两段证据是否对**同一事实**给出**不一致的值**，输出：

```json
{"conflict": true, "fact": "年假天数", "value_a": "5 天", "value_b": "7 天"}
```

口径/范围不同但数值兼容的（如"公司 5 天 vs 法定 5 天"）不算矛盾。

### 2.3 归因策略

| 问题类型 | 优先级 | 理由 |
|---|---|---|
| 含「法律/法定/国家规定」 | 公开法规 | 法定口径优先 |
| 含「行业/外部/参考」且不含「公司」 | 公开资料 | 外部参考口径 |
| 含「旧版/以前/历史」 | 较早版本 | 询问历史版本 |
| 其他（公司政策） | 企业制度 + 较新版本 | 企业制度优先，且用新版本 |

输出格式：

> 注意：年假天数存在差异——员工手册_v2025.md：5 天；员工手册_v2026.md：7 天。
> 本回答以 员工手册_v2026.md 为准（企业制度优先，且采用较新版本）。

## 3. 接入方式

- `/chat`：设置 `CONFLICT_DETECT=true` 时，生成后检测证据冲突并把说明追加到答案末尾；
  默认关闭——每轮会多出若干次 LLM 判定调用，适合"制度类问答"开关式开启；
- **不覆盖流式链路**；
- 也可独立调用：`app.conflicts.detect_conflicts(evidence)` + `conflict_note(...)`。

## 4. 评测

语料：`eval/corpus_conflict/`（独立于主评测集，避免污染 v2/v3 基线）
- 员工手册_v2025 / v2026（版本冲突）
- 劳动法摘要_公开（法定口径）
- 差旅参考_外部（行业参考）

脚本：`python scripts/eval_conflict.py`（15 道用例，真实 API）

指标：
- **冲突检测率**：期望的冲突对是否被检出；
- **归因准确率**：是否按规则选对"以谁为准"。

### 结果

运行：2026-10-25，15 道用例（真实 API）

| 指标 | 值 |
|---|---:|
| **冲突检测率** | **100%（15/15）** |
| **归因准确率** | **100%（15/15）** |

覆盖的冲突类型：
- 版本冲突：员工手册 v2025 vs v2026（年假 5/10 天 → 7/12 天；住宿 500/350 → 600/400）；
- 口径冲突：公司制度 vs 劳动法（7/12 天 vs 法定 5/10/15 天）；
- 外部参考：公司住宿 600/400 vs 行业参考 550/380；
- 历史提问："旧版怎么规定" → 正确切到 2025 版。

调试中发现并修正的两个问题（已写入失败档案思路）：
1. 同文档多分块重复参与判定 → 按来源去重；
2. 字面重叠阈值过严（0.15）导致"公司制度 vs 法规"对未被送入判定 → 降到 0.08，并在 prompt 中给出 scope 示例。

## 5. 局限

1. 判定器与生成器同族，存在偏差；
2. 候选对筛选依赖字符重叠，**同义改写**（"年假" vs "带薪年休假"）可能漏筛；
3. 只处理"两两冲突"，三方以上冲突会生成多条说明，未做合并；
4. 版本号依赖文件名（`v2025`），真实系统应从元数据/生效日期读取；
5. 归因规则是**业务策略**，不同企业可能不同，当前实现是示例；
6. `/chat` 默认关闭，避免每轮都产生额外判定成本。

## 6. 简历话术

> 实现冲突与时效处理：检测同一事实的多来源差异（新旧制度/法规/行业参考），
> 按问题类型显式归因（冲突检测率 100%、归因准确率 100%），避免"同一问题两个答案"。
