# 设计：引用级可验证（Citation Verification）

> 目标：把「回答有来源」升级为「每个事实句都有可验证的证据支撑」。
> 本文档说明设计、接入方式、指标定义与局限。

## 1. 要解决的问题

绝大多数 RAG 项目只做到"给出来源链接"，但：

- 来源可能只是"检索到了"，并没有支持这句话；
- 模型可能把证据 1 的结论写成证据 2 的事实；
- 用户无法判断哪一句有据、哪一句是模型自由发挥。

**引用级可验证** = 对答案逐句检查：这句话引用的证据，是否真的支持它？不支持就删/重写/拒答。

## 2. 设计

### 2.1 证据编号

检索工具（`search_knowledge_base`）把结果格式化为 `[E1] [E2] …`，并记录到请求级上下文
（`app/context.py` 的 `current_evidence`）。多次检索按全局偏移编号，避免编号冲突。

系统提示要求模型**在句末标注 `[E#]`**。

### 2.2 逐句校验

`app/citation.py`：

1. 按句切分（中英文标点）；
2. 提取每句的引用编号 `[E#]`；
3. 对每个（句子, 证据）对做**蕴含判定**（默认 LLM judge，可注入测试替身）；
4. 判定失败/异常 → 保守视为"不支持"。

### 2.3 指标

| 指标 | 定义 | 方向 |
|---|---|---|
| Citation Precision | 被引用的证据中真正支持该句的比例 | 越高越好 |
| Citation Recall | 有引用的句子中至少被一条证据支持的比例 | 越高越好 |
| Uncited Rate | 完全没有引用的句子占比 | 越低越好 |
| Removed Sentences | 因引用不被支持而被删掉的句子数 | 越少越好（最好为 0） |
| Refusal Accuracy | 不可答题正确拒答比例 | 越高越好 |

### 2.4 失败处理策略

`sanitize_answer()`：删除"引用不被支持"的句子；若全部被删光，返回兜底话术
（"根据现有资料无法确认该问题，建议转人工核实"）。

## 3. 接入方式

- **`POST /chat`**：生成后执行校验（`settings.CITATION_VERIFY=true` 时），
  返回 `citations`（证据列表）与 `citation_metrics`（P/R/未引用率/删除句数）；
- **`POST /chat/stream`**：暂不校验（流式逐段下发，无法在生成中回删），
  文档中已注明；后续可在流结束后追加一条"引用校验摘要"事件；
- 关闭方式：`.env` 中 `CITATION_VERIFY=false`。

## 4. 评测

脚本：`python scripts/eval_citation.py --limit 30`
（30 道可答题 + 10 道不可答题；真实检索 + 生成 + 逐句判定）

报告：`docs/eval_citation_report.md`；机器可读：`eval/citation_last_run.json`。

### 结果

运行：2026-10-25，30 道可答题 + 10 道不可答题（真实 API，耗时 340.6s）

| 指标 | 值 |
|---|---:|
| Citation Precision | **0.917** |
| Citation Recall | **0.933** |
| Uncited Rate | 0.151 |
| 删除句子数 | 2 |
| 不可答拒答率 | **100%（10/10）** |

说明：P/R 为逐题平均。Uncited Rate 偏高主要来自列举式答案的收尾句（如"以上为相关规定"），
这类句子不含事实、保留是合理的，后续可区分"事实句/非事实句"再统计。

## 5. 局限（诚实声明）

1. **判定器与生成器同族**（同模型），存在"互相认可"的偏差；理想做法是独立 Judge + 人工抽检；
2. **句子级不等于事实级**：一句含多个事实时，只要部分被支持就算支持（当前实现）；
3. **成本**：每句一次判定调用，长答案成本上升；当前只对含 `[E#]` 的句子判定；
4. **不覆盖流式链路**：流式输出未做删句；
5. **表格/结构化证据**：判定器看到的是 Markdown 表格文本，复杂表头对齐可能误判。

## 6. 简历话术

> 实现引用级可验证问答：答案逐句对齐证据并做蕴含判定，Citation Precision 91.7%、Recall 93.3%；
> 不支持证据的句子自动删除或降级拒答，10 道不可答题拒答率 100%。
