# 失败分类学（Failure Taxonomy）

> 目的：不写"我又加了什么功能"，而是回答**"系统会在哪里出错、为什么、修没修"**。
> 数据全部来自真实运行产物，可一键复现。
>
> 版本说明：第 1–7 节为 v2（24 题）分析，保留为历史；**v3（115 题）结果见第 8 节**。

## 3. 检索失败（6 条，全部 open）

### 3.1 排序噪声（4 条，low）

| 问题 | 受影响策略 | 实际 |
|---|---|---|
| 要给客户发送机密文件，需要走什么流程？ | vector / hybrid / fusion | 金标块排第 2 |
| 服务端口不通，应该先从哪里查起？ | vector / bm25 / hybrid / fusion | 金标块排第 2 |
| 公司应聘一般要面几轮？ | hybrid | 金标块排第 4 |
| 客户来公司开会想连 WiFi，用哪个网络？ | full（生产全流程） | 金标块排第 2 |

**根因**：同一文档的相邻块/近重复块得分略高于金标块。分块带章节前缀后，相邻块的文本高度相似，向量与 BM25 都难以区分。

**影响**：答案通常仍正确（Top-5 里都有），但**引用可能挂到相邻段落**——这正是"引用可验证"要解决的问题。

**建议修复**：块级 MMR 去重、段落级回退（命中后返回整节）、标题加权。

### 3.2 词面不匹配（1 条，high）

> 公司应聘一般要面几轮？ —— BM25 未召回金标块（文档已召回，排第 2）

**根因**：问题用口语"面几轮"，文档写"面试轮次"，BM25 纯词面匹配失效。

**反证**：同一题在 `fusion`（LLM 查询改写）下命中正常 —— 说明**改写是有效补救**，但只在开启改写的策略里生效。

**建议修复**：领域同义词表 + 查询扩展（把"面几轮"扩成"面试 轮次"）。

### 3.3 文档误召回（1 条，high）

> 要给客户发送机密文件，需要走什么流程？ —— BM25 召回的是项目管理系统/云ERP/BI 报表

**根因**："文件 / 流程"是高频通用词，BM25 缺少 IDF 区分度与领域词表，被无关文档抢占。

**建议修复**：领域停用词表、IDF 调权、对低置信度结果做文档级重排。

## 5. 关键发现（诚实结论）

1. **样本量不足**：120 个评测点只产生 6 个检索失败点。要支撑"失败分类学"的统计结论，评测集需扩到 **100+ 题**，并加入冲突、多跳、权限边界、长文档等场景。
2. **质量评测有天花板**：24 题 Judge 全 5.0（100% 达标、0% 幻觉），无法从质量维度发现失败 → 需要更难的题与对抗样本。
3. **瓶颈明确**：Hit@5 100%，但 Top-1 95.8%、排序噪声 4 条 —— 优化方向是**排序精度**，不是召回率。
4. **改写有效**：词面不匹配的题在 `fusion` 下恢复正常，说明查询改写应作为默认策略的组成部分。

## 6. 待修清单（open）与验收标准

| 项 | 动作 | 验收 |
|---|---|---|
| 排序噪声 | 块级 MMR + 段落级回退 | Top-1 ≥ 97%，F-001/002/006 消失 |
| 词面不匹配 | 领域同义词表 + 查询扩展 | Q9 在 BM25 策略下进入 Top-5 |
| 文档误召回 | 停用词表 + IDF 调权 | Q12 在 BM25 策略下命中正确文档 |
| 评测扩容 | 题量 24 → 100+（含冲突/多跳/权限） | 失败样本 ≥ 30 条，分类统计有效 |

## 7. 一句话简历话术

> 建立失败分类学：对 120 个检索评测点 + 24 题质量评测 + 8 次真实故障归因，产出 14 条带根因/修复/验证的失败档案；据此定位瓶颈为**排序精度与领域词面**（而非召回率），并给出可验收的修复清单。
