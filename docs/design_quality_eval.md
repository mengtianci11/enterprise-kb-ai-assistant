# 设计文档：LLM-as-Judge 端到端质量评测（P2-⑩）

> 对应《企业级升级方案 v3.0》P2-⑩：LLM-as-Judge 端到端质量评测。
> 补齐此前评测体系的缺口：**检索指标只能证明「找得到」，证明不了「答得好、没编造」。**

---

## 1. 为什么需要（评测体系的两个维度）

| 维度 | 已有工具 | 回答的问题 | 局限 |
| --- | --- | --- | --- |
| **检索质量** | `scripts/eval_rag.py` | 标准答案分块有没有进 Top-k？排第几？ | 不关心最终回答 |
| **回答质量** | `scripts/eval_quality.py`（本次） | 答对了吗？忠实于资料吗？切题吗？ | 依赖 Judge 模型，可能有偏差 |

行业共识：RAG 评测必须同时覆盖「检索」与「生成」，因为检索命中不代表回答正确——
模型可能：
- 检索对了但**答偏**（相关性低）；
- 答案**混入资料之外的内容**（幻觉，faithfulness 低）；
- 资料不足时**硬编答案**（应回答"资料不足"）。

这正是端到端评测要捕捉的。

---

## 2. 方法：LLM-as-Judge

### 2.1 评测对象

**生产检索管线（查询改写 + 混合召回 + RRF + 重排）→ 单轮生成** 的完整链路。
（不含 Agent 编排：Agent 的职责是"选工具/选路径"，而质量评测关注"给定资料后答得如何"；
如需要，可把 `generate_answer` 换成 Agent 调用，接口已隔离在这一处。）

### 2.2 三个维度（1–5 分）

| 维度 | 定义 | 5 分 | 3 分 | 1 分 |
| --- | --- | --- | --- | --- |
| **correctness** | 与标准答案的事实一致性 | 完全正确 | 部分正确 | 错误 |
| **faithfulness** | 回答能否被检索资料支持 | 全部有依据 | 存在无依据细节 | 完全编造 |
| **relevance** | 是否直接回答用户问题 | 完全切题 | 部分偏题 | 答非所问 |

外加一个布尔字段 `hallucination`：答案是否包含「参考资料与标准答案中都不存在的事实」。
理由：**「不全对」和「编造」是两种风险**，企业场景更怕后者。

### 2.3 Judge 提示词要点

- **只输出 JSON**（可解析、可复现、可入库），容忍代码块/前后解释文字；
- 评分标准写死在提示里（5/3/1 锚点），减少模型漂移；
- `temperature=0`，降低随机性；
- 标准答案取「评测集中标注的 evidence 所在分块」（与检索评测同源，避免人工再写答案）。

### 2.4 稳健性处理

| 风险 | 处理 |
| --- | --- |
| Judge 输出非 JSON | 正则提取代码块 / 首尾大括号；失败计为"评分失败"，不计入分母 |
| 分数越界（0 或 9） | 夹紧到 1–5 |
| 关键字段缺失 | 视为评分失败（不猜测） |
| Judge 调用异常 | 该题记为评分失败，整体继续 |

## 3. 聚合指标

| 指标 | 计算方式 | 用途 |
| --- | --- | --- |
| 平均正确性 | 有效样本 correctness 均值（1–5，另给百分制） | 整体准确率 |
| 平均忠实度 | faithfulness 均值 | 幻觉倾向 |
| 平均相关性 | relevance 均值 | 切题程度 |
| **达标率** | correctness ≥ 4 且 faithfulness ≥ 4 的占比 | 可交付标准 |
| **幻觉率** | faithfulness ≤ 3 的占比 | 风险指标 |

> 「达标率」和「幻觉率」是给业务方看的指标：前者回答"能不能用"，后者回答"敢不敢用"。

---

## 4. 使用方式

```bash
python scripts/eval_quality.py                    # 全量 24 题（约 3–4 分钟）
python scripts/eval_quality.py --sample 6         # 抽查 6 题（快速回归）
python scripts/eval_quality.py --skip-judge       # 只生成回答（不评分，省调用）
python scripts/eval_quality.py --probes-only      # 拒答测试（对抗样本，约 1 分钟）
```

产物：
- `docs/eval_quality_report.md`：可读报告（汇总 + 逐题明细 + 评审理由）
- `eval/quality_last_run.json`：机器可读（供后续接入质量门禁）

## 5. 验证证据

### 5.1 主评测（24 题，真实 API）

| 指标 | 数值 |
| --- | --- |
| 平均正确性 | 5.0 / 5 |
| 平均忠实度 | 5.0 / 5 |
| 平均相关性 | 5.0 / 5 |
| 达标率（正确≥4 且忠实≥4） | 100% |
| 幻觉率（忠实≤3） | 0% |

> ⚠️ **天花板效应说明（诚实记录）**：24 道题均直接由语料构造，且 Judge 与生成模型同族、
> 偏宽松，因此指标触顶。这类"全满分"不能证明系统对任意问题都完美，
> 只说明**在给定语料与题型上，答案正确且忠实**。为此额外做了拒答测试（见 5.2）。

### 5.2 拒答测试（对抗样本，5 题）

问题均为知识库无法回答的内容（CEO 姓名、营收、股票代码、报销次数、上市计划）。
关键点：检索仍会返回 5 条**无关**资料（不是空结果），模型必须在这种干扰下依然拒答。

| 指标 | 数值 |
| --- | --- |
| 正确拒答率（correctness ≥ 4） | **100%**（5/5） |
| 编造率（hallucination=true） | **0%** |

示例（P1「公司的 CEO 叫什么名字？」）：
> 检索返回 5 条无关资料（员工手册总则、产品概览…）→ 回答：
> 「根据提供的资料，无法回答公司CEO的名字。资料中未包含任何关于公司高管姓名的信息。来源：无相关依据」

### 5.3 工程验证

| 项目 | 结果 |
| --- | --- |
| 纯逻辑单测 | 9 项（JSON 解析：代码块/夹紧/缺字段/非法；聚合：分母只算有效样本、空样本、全失败） |
| 全量测试 | 147 项全部通过（含本模块新增 9 项） |
| 产物 | `docs/eval_quality_report.md`、`docs/eval_quality_probes.md`、`eval/quality_last_run.json`、`eval/quality_probes_last_run.json` |

## 6. 取舍与边界

| 决策 | 收益 | 代价 |
| --- | --- | --- |
| 用 Judge 模型评质量 | 可自动化、可复现、成本可控 | Judge 自身有偏差（同族模型可能偏袒）；建议重要决策人工抽检 |
| 评测对象为「检索+生成」链路 | 聚焦回答质量，变量可控 | 不含 Agent 编排的路径选择质量 |
| 标准答案取 evidence 分块 | 与检索评测同源、零人工成本 | 覆盖的是"分块内容"，不是完整人工答案 |
| temperature=0 + 严格 JSON | 可复现 | 无法捕捉模型在多种表述下的稳定性 |

---

## 7. 后续

1. 把质量指标接入 CI 门禁（与检索指标同基线机制，阈值可用 `correctness ≥ 4.5`、`幻觉率 ≤ 5%`）；
2. **人工抽检校准**：随机抽 20% 样本人工打分，计算与 Judge 的一致性（Cohen's Kappa）；
3. 多 Judge 投票（3 个模型取中位数）降低单模型偏差；
4. 把达标率与幻觉率做成趋势看板（配合 P2-⑧ 的可观测）。
